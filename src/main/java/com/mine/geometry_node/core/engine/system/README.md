# 引擎功能系统

这里按业务能力划分功能域；各域内部再按真实职责划分包。目录不是按类名后缀、文件数量或客户端/服务端字样机械分组。模型、协议和工具也可能被客户端使用，不能因为位于 `core.engine.system` 就认为它们仅供服务端调用。

## 目录职责

| 功能域 | 内部分组与边界 |
| --- | --- |
| `asset` | 根包保留共享的条目、元数据和相对路径契约。`type` 管理类型识别、能力声明和生命周期分发；`repository` 管理仓库路径、权限、文件事务、异步提交和元数据缓存。 |
| `asset/preview` | 公共预览契约与服务入口；`generator` 管理生成能力及实现，`generator/schematic` 是可复用的结构缩略图算法，`store` 管理派生产物的落盘和维护。 |
| `asset/transfer` | 传输入口及限制；`model` 是任务、文件、策略、状态和结果快照，`io` 是有界 IO、散列和原子提交。入口只有一个服务，不单设 `service` 空层。 |
| `chunkloading` | 实体持有的强加载配置、票据恢复和持久化。三个类共同组成一个功能，不拆成单类配置/服务/存储包。 |
| `datalibrary` | `model` 管理条目、目录树、身份、指纹、值表示；`storage` 管理文档 JSON、加载诊断、文件原子写入和路径；`service` 管理权威快照、元数据能力和异步仓库接入；`runtime` 管理蓝图写入及等待。 |
| `scopeddata` | GLOBAL／维度 PUBLIC 数据的远程权限、目录、读取、CAS 与连接限速；复用 scoped state 存储，不承载 UI 或新的字典容器。 |
| `dialogue` | 根包是运行时、会话生命周期、等待及交易执行的内部协作簇。`model`/`model/shop` 定义页面数据，`presenter` 定义展示通道，`richtext` 处理文本规范和解析，`storage` 管理交易次数的持久状态。 |
| `display` | 原生 Display 实体的姿态、pivot 和变换控制；不与 CPU 模型的数学表示混放。 |
| `entity` | 原生 Interaction 实体创建边界；不额外建立单类 `factory` 包。 |
| `entityeditor` | 实体属性、装备、绑定图的读取、验证及受保护修改。协调器、适配器和事务内部类型保持同包，避免将内部状态暴露为公共 API。 |
| `entitypreview` | 根包是服务和内部限流器；`appearance` 捕获及清理外观，`protocol` 定义预览目标、限制及 NBT 编码。 |
| `image` | 运行时图片资源的格式、校验、来源、配置和服务；不同于 `asset/preview` 生成的派生缩略图。 |
| `marker` | 根包管理实例服务和持久化；`model` 定义地址、锚点、受众、请求及实例，`type` 管理类型契约、注册和内建类型。 |
| `model/asset` | 不可变 CPU 模型、网格、场景、身份、清单和预算契约。 |
| `model/io` | 与格式无关的字节源、资源提供者、路径处理及取消契约。 |
| `model/gltf` | GLB/glTF 容器、访问器、场景、几何、材质、纹理及导入预算。格式内部协作类保持同包。 |
| `model/collision` | 共享碰撞几何、配置和变换；`generation` 聚合碰撞构建、缓存发布及内部算法，`runtime` 管理世界实例、空间查询、运动求解和采样。 |
| `model/runtime` | 加载句柄、仓库、租约、实例及姿态的所有权和生命周期。 |
| `model/capability`、`model/diagnostic`、`model/math` | 分别是能力证据、结构化错误和公共数学表示。虽然目前较小，但边界明确，保留独立语义。 |
| `quest` | 根包管理任务、条件和事件；`model` 是领域数据，`status` 是状态定义及注册，`storage` 是实体任务附件，`screen` 是屏幕会话和视图装配。 |
| `scene` | 权威场景文档、类型验证、原生实体适配和服务；`property` 管理属性描述、节点映射和检查器 schema，`geometry` 管理几何类型及变换，`volume` 管理区域和碰撞运行时。 |
| `schematic` | 执行、放置持久化、调试同步和投影。当前规模与包内协作关系适合聚合，不拆出多个一两个类的小包。 |
| `viewport` | 相机观察者、区块区域、追踪适配和短期租约；`entity` 管理视口原生实体编辑、恢复及移动命令。 |
| `worldquery` | 根包是调度、收集、内建提供者和宿主适配；`model` 是不可变条目、查询、结果和匹配规则，`provider` 是提供者扩展契约，`metadata` 是 tag/data 能力租约及编辑。 |

## 依赖和可见性

优先让描述模型和扩展契约被执行层依赖。`worldquery` 的模型不依赖查询执行或元数据编辑；注册类型、服务、存储也应维持各自边界。已有涉及宿主服务的双向调用不能仅靠换目录消除，不能通过增加同名转发类来假装解决。

包内可见性是实现边界。对话会话、实体编辑事务、碰撞构建算法等需要相互访问内部成员的类整体归类；不为拆目录而将它们改成公共 API。测试随被测职责和包内访问边界归类，跨域集成测试保留自己的入口。

Java 包迁移不改变世界数据目录、缓存标识、图类型 ID、网络消息 ID、翻译键或文件格式。资料库仍使用 `<world>/data/geometry_node/data_library.json`，世界资产仍位于 `<world>/geometry_nodes/`。

## 本轮整理

已审查原 `system` 下全部 16 个功能域及其子目录。移除了只承接单一子域的 `data/library` 和 `visual/image` 容器层，统一为 `datalibrary` 和 `image`；`chunk_loading` 改为 `chunkloading`。其余按上表归类，并同步源代码引用、测试包和相关文档路径。

`entityeditor`、部分 `scene` 类和模型算法内部簇仍保持聚合。这是基于包内协作及依赖方向的选择；继续拆分需要先设计新的内部协作边界，不能直接拆包再扩大权限。

本轮保留全部 271 个主类，迁移其中 91 个主类及 31 个测试类。编译、JAR 构建和 521 项相关回归通过；已核对迁移后包名与路径、旧类型引用、Git 忽略规则和 JAR 类清单。没有启动游戏进行视觉验证。
