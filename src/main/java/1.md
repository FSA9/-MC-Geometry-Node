16. 父级

1. 运行时开关节点
   现在 enabled 是静态配置。还没有 Enable Area Trigger / Disable Area Trigger 这种动作节点。
2. 实体过滤
   现在基本是检测非旁观者实体。后面应该加：
   只检测玩家 / 生物 / 指定 entity type / tag / team / predicate。
3. 动态区域或跟随实体
   现在区域参数是静态 hidden pin。也就是说适合固定世界区域。
   如果要做“跟随某个实体的检测盒”，需要再加 relativeToOwner 或专门的跟随区域节点。
4. 真正的区域对象
   现在“事件节点本身就是区域”。更高级的版本可以做：
   Register Area Trigger -> triggerId -> On Area Enter/Exit 监听 triggerId
   这样更像 UE 的组件/Actor。
5. 更多形状
   当前核心是旋转盒 OBB。后面可以加：
   AABB / Sphere / Capsule / Cylinder。
   球形和 AABB 会更便宜。
6. 大规模性能优化
   现在已经做了合并查询、interval、UUID 状态，但还没做编译期 Area lookup。
   如果以后一个世界里有几百上千个区域，应该让 RuntimeGraphIndex 预计算 area 节点索引，减少 tick 扫描成本。
7. 实体消失时的 Exit 语义
   现在实体离开区域会触发 Exit；但如果实体直接死亡、卸载、切维度，可能查不到实体对象，Exit 会被跳过。
   要严格完整，需要给 Exit 支持 UUID 输出，或者专门处理 despawn/dimension change。

所以结论：当前版本已经能实际用，核心功能是完整的；距离真正“UE 风格完整系统”，主要差运行时管理、过滤、动态区域、更多形状和大规模索引优化。

DialogueRuntime 现在能创建 session、选择、关闭，但生产级还需要处理：

- 玩家下线。
- 玩家死亡。

- 距离过远。

这些是 RPG 地图真正会遇到的问题。

8. 和行为树/任务系统的联动还没开始

真正 UE-like 的路线里，对话树不会是孤岛。

未来应该能做到：

对话选项 -> 设置 NPC 黑板变量
对话节点 -> 发起任务
任务状态 -> 控制选项显示
行为树状态 -> 影响 NPC 对话内容
对话结束 -> 通知行为树继续巡逻/战斗/跟随

所以需要提前设计共享服务：

Shared Blackboard
Quest State
Dialogue Flags
Entity Binding
Graph Event Bridge

现在还只是对话 runtime 自己闭环。

我建议下一阶段顺序

1. 先做 DialogueContext 升级：加入 speakerEntity / targetEntity / entryId / variables。
2. 做独立对话图入口：DialogueEntry、OpenDialogueTree、真实 DialogueGraphLauncher。
3. 做文本资源规范：dialogues/<locale>/*.json 或 .txt/.properties，支持加载和 fallback。
4. 补通用条件节点：Equal / Contains / And / Or / CompareNumber。
5. 拆分 DialogueRuntime 包结构。
6. 再开始做更高级的 UI 表现、富文本、打字机、头像、语音、任务联动。

一句话总结：现在是“蓝图驱动的对话页 MVP”，不是完整“独立对话树引擎”。下一步真正拉开档次的是独立 Dialogue Graph + 会话上下文黑板 + 文本资源系统。







最高优先级

1. 事件分发缺少 eventType -> graphIds 索引
   现在 GraphEngine.dispatchEvent 会扫全局图和目标实体绑定图，再对每张图 findNodesByType。高频事件下成本是 事件数 * 绑定图数。
   证据：src/main/java/com/mine/geometry_node/core/engine/blueprint/runtime/GraphEngine.java:88、src/main/java/com/mine/geometry_node/core/engine/blueprint/runtime/GraphEngine.java:225。
   建议：抽 GraphSubscriptionIndex，bind/reload 时维护普通事件、receive_blueprint、tick/area 等索引；dispatch 时只遍历命中图。
2. VM 内部 ExecutionThread 仍从公共事件 API 泄漏
   GraphEngine/BlueprintRuntime 还有 Consumer<GraphProcess.ExecutionThread> 入口，mixin 也在直接 setEventData。
   证据：src/main/java/com/mine/geometry_node/core/engine/blueprint/runtime/GraphEngine.java:70、src/main/java/com/mine/geometry_node/mixin/ProjectileShootMixin.java:39、src/main/java/com/mine/geometry_node/mixin/
   ProjectileHitMixin.java:53。
   建议：先全部迁到 GraphEventData.of(...) / Map<String,Object>；然后把线程 initializer overload 降级为 private/internal，后续才好安全拆 VM。
3. 空闲常驻进程每 tick 仍被复制和调用
   GraphContainer.tick() 每 tick List.copyOf(processes.values())，但 GraphProcess.tick() 主要只处理 sleeping thread/rebase。大量无 wait 的绑定图会有稳定小开销。
   证据：src/main/java/com/mine/geometry_node/core/engine/blueprint/attachment/GraphContainer.java:42、src/main/java/com/mine/geometry_node/core/engine/blueprint/runtime/GraphProcess.java:197。
   建议：容器维护“需要 tick 的进程”或按 nextWakeTick 的队列；Wait/scheduleNode/load rebase 才入队。

中优先级
4. OnEntityTick 是明显热路径
   每个实体 tick 遍历绑定图、查 tick 节点、读 interval/offset。
   证据：src/main/java/com/mine/geometry_node/core/engine/blueprint/event/dispatcher/EntityDispatcher.java:100、src/main/java/com/mine/geometry_node/core/engine/blueprint/event/dispatcher/EntityDispatcher.java:114。
   建议：编译期生成 EntityTickSpec(nodeId, interval, offset)，只有含 tick spec 的图注册实体 tick。

5. ExecutionContext 太宽
   普通节点拿到变量、输入、事件数据、持久属性、分支 join、schedule、视觉广播等全部能力。
   证据：src/main/java/com/mine/geometry_node/core/engine/blueprint/runtime/ExecutionContext.java:21、src/main/java/com/mine/geometry_node/core/engine/blueprint/runtime/ExecutionContext.java:161、src/main/java/com/mine/
   geometry_node/core/node/nodes/BaseNode.java:32。
   建议：先加窄接口，不立刻改行为：NodeContext、ControlFlowContext、VisualContext、PersistentAttributeContext。后续控制流节点才依赖特权接口。
6. GraphEngine 职责过多，GraphContainer.getProcess 有读方法副作用
   GraphEngine 同时管绑定、订阅、进程创建、graph index 查找、debug dirty；getProcess 会隐式创建/替换进程。
   证据：src/main/java/com/mine/geometry_node/core/engine/blueprint/runtime/GraphEngine.java:31、src/main/java/com/mine/geometry_node/core/engine/blueprint/attachment/GraphContainer.java:51。
   建议：保留 GraphEngine facade，内部拆 BlueprintGraphResolver、GraphProcessRepository、GraphSubscriptionIndex；getProcess 拆成 findProcess / getOrCreateProcess。
