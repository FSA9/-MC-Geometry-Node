试想一下：在异步模式下，循环每 1 秒跑一次，一共跑 3 次。如果玩家在第 1.5 秒的时候再次放了一个方块（再次触发了这条线）。
此时，原有的循环还在跑，新的循环又进来了，它们会争抢同一个 TempData（ForLoop_X_index），导致逻辑乱套！
目前的解决方案是够用的，但为了未来让你的引擎更像虚幻引擎的 Blueprint 那样健壮，建议你了解以下两种做法（现在不用改，记在心里即可）：
做法 A：忽略重入（Ignore）
在 ForLoop 中判断：如果发现 getTempData(cursorKey) 已经存在，并且当前节点处于异步执行中，直接丢弃新来的执行流（抛弃玩家第 1.5 秒的放置事件），直到循环跑完为止。
做法 B：执行流私有状态（Token / Thread State）
不在 GraphProcess 的 TempData 中存 index，而是把 index 存在 ExecutionThread（协程）自己的局部栈或者 eventRegisters 里。这样，每次放置方块都是一个完全独立的线程，它们互不干扰，甚至可以同时并行跑两个不同的 ForLoop。
