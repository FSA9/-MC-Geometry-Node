同步分支里放 Delay 会破坏执行流

executeBranchSync() 是给 ForLoop / ForEachLoop 这种同步循环用的。它的意思是：马上执行 loop 分支，等分支跑完再回来继续循环。

但如果 loop 分支里面有 Delay，节点会返回 ExecutionResult.Wait，当前线程被塞进 sleepingThreads。问题是 executeBranchSync() 后面又把原来的 currentFlowId/executionStack 恢复回去了。

结果就是：

- 线程已经被标记成等待。
- 等待线程的续点又被父流程覆盖。
- 醒来后可能跑错路径，或者父流程状态也变得不干净。
