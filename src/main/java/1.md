• 现在这个 MVP 已经有了“能跑起来”的核心：

- 蓝图节点触发对话。
- BeginDialogue 建立对话上下文。
- ShowDialoguePage 打开一页对话。
- 支持 default 和 rpg 两种样式。
- 玩家选择后通过 DialogueRuntime 恢复执行流。
- 支持 closed、flow_out、动态选项。
- 文本已有 text_key + fallback_text 的雏形。

但距离真正完善、对标 UE 的专业对话树，还差这些核心层级。

3. 文本资源系统还没真正专业化

现在 text_key + fallback_text 是对的，但还不够。

真正对标 UE/专业 RPG，需要：

dialogues/
zh_cn/
blacksmith.json
en_us/
blacksmith.json

或者更接近翻译友好的格式：

{
"blacksmith.greeting": "你好，旅行者。",
"blacksmith.choice.trade": "我想看看商品。",
"blacksmith.choice.quest": "有什么需要帮忙的吗？"
}

还需要：

- 按玩家语言解析。
- world/save 内文本覆盖。
- resource/data pack 文本覆盖。
- 缺失 key 诊断。
- 热重载。
- 导出待翻译 key。
- 支持富文本格式，后续可接 Markdown/样式 token。

目前这块只是接口雏形，不算完整系统。

6. 会话生命周期需要完善

DialogueRuntime 现在能创建 session、选择、关闭，但生产级还需要处理：

- 玩家下线。
- 玩家死亡。
- NPC 消失。
- 距离过远。
- 维度切换。
- 图热更新。
- 服务器关闭。
- 同一个玩家重复打开对话。
- 多人同时和一个 NPC 对话。
- 对话超时。
- 外部强制关闭。
- session 调试信息。

这些是 RPG 地图真正会遇到的问题。

8. 和行为树/任务系统的联动还没开始

真正 UE-like 的路线里，对话树不会是孤岛。

未来应该能做到：

对话选项 -> 设置 NPC 黑板变量
对话节点 -> 发起任务
任务状态 -> 控制选项显示
行为树状态 -> 影响 NPC 对话内容
对话结束 -> 通知行为树继续巡逻/战斗/跟随

所以需要提前设计共享服务：

Shared Blackboard
Quest State
Dialogue Flags
Entity Binding
Graph Event Bridge

现在还只是对话 runtime 自己闭环。

我建议下一阶段顺序

1. 先做 DialogueContext 升级：加入 speakerEntity / targetEntity / entryId / variables。
2. 做独立对话图入口：DialogueEntry、OpenDialogueTree、真实 DialogueGraphLauncher。
3. 做文本资源规范：dialogues/<locale>/*.json 或 .txt/.properties，支持加载和 fallback。
4. 补通用条件节点：Equal / Contains / And / Or / CompareNumber。
5. 拆分 DialogueRuntime 包结构。
6. 再开始做更高级的 UI 表现、富文本、打字机、头像、语音、任务联动。

一句话总结：现在是“蓝图驱动的对话页 MVP”，不是完整“独立对话树引擎”。下一步真正拉开档次的是独立 Dialogue Graph + 会话上下文黑板 + 文本资源系统。
